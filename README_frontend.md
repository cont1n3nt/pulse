# Frontend: страница аккаунта

Frontend состоит из `frontend/index.html`, `frontend/style.css` и `frontend/app.js`. Сборка и отдельный сервер не нужны: FastAPI отдаёт страницу по `/`, а CSS и JavaScript — по `/static`.

## Запуск

Все команды выполняются из корня проекта. Нужен Python 3.11 или новее.

1. Создайте и активируйте виртуальное окружение (Windows PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

2. Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

3. Если файла `.env` ещё нет, создайте его из примера:

```powershell
Copy-Item .env.example .env
```

Сгенерируйте серверный ключ:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте выведенное значение в `.env` вместо `replace-me` в строке `PULSE_AUTH_KEY=replace-me`. Если в `.env` уже есть рабочий `PULSE_AUTH_KEY`, оставьте его как есть.

4. Запустите сайт:

```powershell
python -m uvicorn backend.main:app --reload
```

Откройте http://127.0.0.1:8000/. Отдельно запускать frontend не нужно. При следующих запусках активируйте `.venv` и повторите команду из шага 4.

## Коды и ключи

- **Код доступа** создаётся отдельно для каждого аккаунта через `secrets.token_urlsafe(32)`. При перевыпуске создаётся новый код, а старый перестаёт подходить для входа. Пользователь сохраняет свой код самостоятельно.
- **Токен cookie-сессии** создаётся отдельно при регистрации и каждом входе. Cookie содержит этот случайный токен, а не постоянный код доступа. Токен не записывается в `localStorage` или `sessionStorage`.
- **`PULSE_AUTH_KEY`** — один секретный серверный ключ для вычисления HMAC-хешей кодов доступа. Он хранится в `.env`, не отправляется в браузер и не является кодом пользователя. В SQLite сохраняются только хеши кодов.

Строка `PULSE_AUTH_KEY=replace-me` в `.env.example` — заглушка, а не рабочий ключ. Сервер с ней не запускается: требуется случайный ключ длиной не менее 32 байт. **Сохраните `.env` и не меняйте `PULSE_AUTH_KEY` после выдачи кодов:** с другим серверным ключом старые коды перестанут проверяться.

## Поведение страницы

- Оформление повторяет предоставленный макет «Тихо». Поездки и беседа на экране демонстрационные и не подключены к API; правой панели с отелями нет.
- Верхней панели нет. Левая панель закреплена у края экрана и остаётся на месте при прокрутке чата.
- Иконка профиля внизу открывает компактную панель аккаунта. Её можно перетащить мышью или пальцем за заголовок; кнопка × сворачивает панель.
- В панели входа можно ввести или вставить код, показать или скрыть его, отменить вход. Ошибка выводится рядом с формой; во время отправки повторное нажатие блокируется.
- На узком экране боковая панель становится компактной, а окно аккаунта умещается рядом с ней.
- При создании аккаунта или перевыпуске кода панель открывается автоматически, чтобы новый код можно было сохранить.
- При открытии страница запрашивает `GET /api/auth/me`. Если действующей сессии нет, вызывает `POST /api/auth/guest` и показывает новый ID и код доступа.
- Код можно показать и скопировать нажатием на само поле кода сразу после создания аккаунта или перевыпуска. После обновления страницы исходный код недоступен: сохраните его заранее.
- «Войти в существующий аккаунт» отправляет код через `POST /api/auth/login` и переключает текущую сессию на найденный аккаунт.
- «Перевыпустить код» после подтверждения вызывает `POST /api/auth/rotate`. Старый код перестаёт подходить для нового входа.

Код не сохраняется в `localStorage` или `sessionStorage`. Cookie-сессия недоступна JavaScript (`HttpOnly`). Для HTTPS cookie получает флаг `Secure`.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют первый и повторный вход, второй браузер, смену кода, cookie и защиту запросов. Сессии хранятся в памяти backend и пропадают после его перезапуска; войти снова можно по сохранённому коду.
