# Pulse — ИИ-агент, который собирает поездку целиком (трек Островок «О!дин запрос»)

Из одного сообщения («из Москвы на майские, двое с ребёнком, до 150 тысяч») агент сам понимает даты
и скрытые требования. Он собирает 2–3 готовые поездки: самолёт или поезд, трансфер и отель с одной
итоговой суммой. Затем объясняет разницу в рублях, проверяет состыковки и оформляет заказ по кнопке.
После покупки переносит заказ на другие даты и добавляет трансфер к купленному отелю.

Главная идея: **суммы и состыковки считает код, а модель только объясняет.** Поэтому агенту можно
доверить деньги: итог всегда сходится, а поездку с ночным прилётом после заезда или хостелом для семьи
нельзя оплатить.

- Видео-скринкаст: **<ссылка на видео>**
- Развёрнутый сервис: https://ostrovok.kosmoweb.ru
- Локация — Большой Сочи (1 358 отелей из OpenStreetMap). Всё о месте вынесено из кода в один файл,
  поэтому новый город добавляется без правок агента (см. «Локации»).

## Быстрый старт

```bash
git clone https://github.com/cont1n3nt/pulse.git
cd pulse
cp .env.example .env   # впишите LLM_API_KEY (и по желанию TRAVELPAYOUTS_TOKEN, YANDEX_RASP_KEY)
docker compose up --build
# открыть http://localhost:8080
```

Для жюри ключи лежат в `secrets.env.age` (отдельные ключи с лимитом расходов). Расшифруйте его в `.env`
своим ключом age вместо `cp .env.example .env`:

```bash
age -d -i <ваш-ключ> -o .env secrets.env.age
```

Нужны Docker и Docker Compose v2. Сборка занимает около минуты. Когда сервис готов,
`docker compose ps` показывает `healthy`.

Те же действия через `make`:

| Команда | Что делает |
|---|---|
| `make env` | создать `.env` из примера, если его нет |
| `make up` | собрать и запустить в фоне |
| `make logs` | журнал агента: каждый вызов модели и инструмента со временем и токенами |
| `make health` | проверить `/health` изнутри контейнера |
| `make test` | юнит-тесты детерминированного ядра, без ключей и сети (нужен uv) |
| `make evals` | прогнать сценарии на настоящей модели, отчёт в `evals/results/` |
| `make seed LOCATION=sochi` | заново выгрузить отели локации из OpenStreetMap (нужен uv и интернет) |
| `make secrets` | зашифровать `.env` в `secrets.env.age` ключом жюри (нужен age) |
| `make down` / `make reset` | остановить; остановить и стереть данные |

## Модель

Провайдер — [smartapi.pro](https://api.smartapi.pro/v1) (OpenAI-совместимый API), модель — **`claude-haiku-5-5`**.
Это значения по умолчанию: на них сделаны все прогоны ниже. Подойдёт любая OpenAI-совместимая модель
с вызовом инструментов: задайте `LLM_BASE_URL` и `LLM_MODEL`.

## Зависимости и переменные окружения

Рекомендованные ресурсы: 1 CPU, 512 МБ RAM. В простое сервис занимает около 100 МБ. Образ весит около
460 МБ на диске и около 100 МБ в сжатом виде.

Внешних сервисов внутри compose нет. Всё хранится в SQLite в томе `pulse-data` (`/app/data`):

- пользователи и чаты;
- состояние диалогов LangGraph;
- долговременная память;
- заказы;
- кэш фото и календаря;
- ключ подписи сессий, если он не задан в `.env`.

Пустое значение в `.env` — то же, что не задано.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_API_KEY` | — (**обязательно**) | ключ провайдера модели |
| `LLM_BASE_URL` | `https://api.smartapi.pro/v1` | адрес OpenAI-совместимого API |
| `LLM_MODEL` | `claude-haiku-5-5` | модель агента |
| `LLM_FALLBACK_MODELS` | пусто | запасные модели через запятую: при 429 или сбое запрос уходит следующей |
| `STRUCTURED_REPLY` | `1` | `0`: финальный ответ обычным текстом, для слабых в tool calling моделей |
| `TRAVELPAYOUTS_TOKEN` | пусто | цены перелётов Aviasales; без него поездка собирается поездом |
| `YANDEX_RASP_KEY` | пусто | настоящее расписание поездов из [API Яндекс Расписаний](https://yandex.ru/dev/rasp/doc/ru/) (бесплатный ключ в [кабинете разработчика](https://developer.tech.yandex.ru)); без него — демо-расписание |
| `PULSE_LOCATION` | `sochi` | локация агента: папка в `backend/seed/` с `location.json` |
| `PULSE_AUTH_KEY` | генерируется | ключ подписи сессий, от 32 байт; без него создаётся при первом запуске и хранится в томе |
| `PULSE_DB_PATH` | `/app/data/pulse.sqlite3` в Docker | файл базы пользователей и чатов |
| `DATA_DIR` | `/app/data` в Docker | память агента, заказы, кэши |
| `HTTP_TIMEOUT` | `20` | таймаут внешних API, секунд |
| `AGENT_RECURSION_LIMIT` | `60` | предел шагов агента за ход |
| `LOG_LEVEL` | `INFO` | подробность логов |
| `LANGSMITH_TRACING`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT` | выключено | трассировка каждого хода в LangSmith |

Порт фиксированный, 8080. Для HTTPS-домена поставьте перед сервисом nginx или Caddy и передавайте
`Host` и `X-Forwarded-Proto`. Uvicorn запущен с `--proxy-headers`. Для потока ответа отключите буферизацию:
в nginx это `proxy_buffering off`, ответ уже помечен `X-Accel-Buffering: no`.

## Сидирование

Ничего делать не нужно. Отели лежат в репозитории (`backend/seed/sochi/hotels.json`) и попадают в образ. Таблицы создаются при первом старте. Обновить выгрузку из OpenStreetMap
(нужен интернет, 1–5 минут):

```bash
make seed LOCATION=sochi            # или: uv run python scripts/fetch_osm.py sochi --refresh
```

## Маршруты и доступ

- `/` — веб-интерфейс: чат слева, карточки пакетов, корзина и маршрут по часам справа.
- `/health` — `200 OK`, `{"status": "ok"}` (проверяет и базу).
- `POST /api/chat` — сообщение агенту, ответ потоком SSE. Остальные роуты описаны в [docs/AGENT.md](docs/AGENT.md).
- Тестовый пользователь не нужен. При первом заходе создаётся гостевой аккаунт. Код доступа для входа
  с другого устройства есть в профиле.

Проверить без браузера: `make test` (ядро, без ключей) и `make evals` (агент на настоящей модели).

## Что умеет агент — по задачам трека

| Задача трека | Как сделано |
|---|---|
| 1. Понимание запроса | Агент понимает явные условия и скрытые требования: «с ребёнком» — без хостелов и с отметкой для детей, «с собакой» — с животными, «потише» — не первая линия. «На майские» берётся из производственного календаря, «на выходные» — из ближайшей пятницы. Уточнение — только если не хватает дат или состава гостей, один вопрос. Остальное агент додумывает и называет допущением. |
| 2. Вдохновение | «Не знаем, какой район» или «хотим тихо» — агент сам выбирает район по характеру поездки, объясняет выбор и называет запасной вариант. Желание не по сезону («тёплое море в ноябре», «лыжи в июле») — честно называет, как будет, и предлагает, что подойдёт. |
| 3. Подбор и сравнение | Готовые пакеты «Эконом / Оптимум / Комфорт»: дорога туда и обратно, трансфер и отель с одной суммой. Сравнение в рублях: «Комфорт дороже на 14 000 ₽ — 150 м до моря вместо 900». Даты подешевле — сдвиг на ±3 дня. |
| 4. Объяснение | Что получаешь и чем жертвуешь в каждом пакете. Честные пометки «демо» и «нет данных», без выдуманных отзывов. |
| 5. Сборка и покупка | Корзина, проверка состыковок (прилёт после заезда, ночь без жилья, долгая дорога с ребёнком, хостел для семьи, бюджет), маршрут по часам с проблемой у своего шага. Оплата только по кнопке (interrupt LangGraph), номер заказа. |
| 6. Пересборка | «На два дня позже», «дешевле», «поездом» — агент меняет только названное, говорит, что изменилось, и предлагает заменить выбор в корзине. |
| Доп.: после покупки | «Перенесите на день позже» — тот же отель, рейсы и трансфер на новые даты с разницей в рублях; старый заказ отменяется только после оплаты нового. «Добавьте трансфер» — такси к купленному отелю отдельным заказом. Ранний заезд — честно как просьба к отелю. |
| Доп.: поезда | «Поездом» или «не любим летать» — пакеты с поездом до станции у отеля и такси от вокзала. Если рейсов нет, поездка собирается поездом. Поездку самолётом агент сравнивает с поездкой поездом. |
| Доп.: память | Город вылета, состав семьи, предпочтения и факты («всегда с завтраком») сохраняются между чатами. Их видно в профиле, там же их можно стереть. |
| Доп.: метрики | Сценарии на настоящей модели и метрики качества, см. ниже. |
| Доп.: мобильная версия | Адаптивная вёрстка. |

Суммы считает код, а не модель. Пакеты собирает `backend/agent/packages.py`, проверку делает
`backend/agent/trip.py`, перенос заказа — `backend/agent/aftersale.py`. Модель выбирает инструменты
и объясняет результат, поэтому итог всегда сходится.

Устойчивость:

- повтор вызова и запасные модели;
- повтор сетевых инструментов, лимиты вызовов;
- фильтр промпт-инъекций во входе и в данных отелей;
- разбор ответа модели, которая напечатала вызов инструмента текстом;
- очистка разметки в ответе.

## Три стороны: путешественник, отель, Островок

**Путешественник** пишет одно сообщение и получает три понятные поездки с одной суммой вместо
десятка вкладок с билетами, отелями и такси. Перед оплатой код проверяет, что всё стыкуется.

**Отель хочет подходящих гостей, а не любых.** Агент сводит к минимуму брони, которые заканчиваются
конфликтом на ресепшене или отменой:

- хостел не продаётся семье с ребёнком (блокер, а не совет);
- удобство, которое не подтверждено данными («с животными», «для детей»), не обещается гостю:
  агент говорит «уточните у отеля», а проверка помечает это предупреждением;
- гость, который прилетает в 6 утра, заранее знает, что заселение с 14:00. Ранний заезд он запрашивает
  у отеля до приезда, а не спорит на ресепшене;
- условия отмены и питание называются до оплаты, а описание отеля строится из фактов карты
  (расстояние до моря, дорога, что рядом), без выдуманных отзывов;
- перенос дат — новая бронь того же отеля, а не отмена.

**Островок** получает поездку целиком в одной корзине (отель + дорога + трансфер) и меньше отмен
и обращений в поддержку. Подробнее — в разделе ниже.

## Как встроить в Островок

Агент собран как набор заменяемых блоков вокруг контрактов (`backend/agent/contracts.py`). Агент,
проверки и интерфейс работают с моделями `HotelOption`, `FlightOption`, `TransferOption`, `Order`.
Откуда пришли данные, им всё равно.

| Блок | Сейчас | В Островке |
|---|---|---|
| Отели: поиск, цена, наличие, питание, отмена | `adapters/hotels.py`: объекты OSM, цена — демо-модель | API инвентаря и тарифов Островка: та же функция `search`/`quote`, `is_demo=False` |
| Перелёты | `adapters/aviasales.py`: кэш цен Travelpayouts | партнёрский API билетов с бронированием |
| Поезда | `adapters/trains.py` + Яндекс Расписания | партнёр ж/д билетов |
| Трансфер | `hotels.transfer`: маршрут OSRM, демо-тариф | партнёр трансферов |
| Заказ и оплата | `orders.py`: SQLite, оплата имитируется | бронирование и платёжный шлюз; точка подтверждения (`interrupt` в `checkout`) остаётся той же |
| Локации | `backend/seed/<id>/location.json` + выгрузка OSM | регионы Островка: районы, аэропорты и вокзалы из справочника |
| Память | хранилище LangGraph в SQLite | профиль пользователя Островка |
| Состояние диалогов | `SqliteSaver` | `PostgresSaver` той же LangGraph: несколько воркеров |

Как подключать:

- **Чат на сайте и в приложении**: SSE API (`POST /api/chat`) и события `block` (`packages`, `cart`, `order`,
  `confirm`) — фронт рисует карточки из своих компонентов. Сейчас — веб-клиент без сборки в `frontend/`.
- **Без чата**: детерминированное ядро — сборка пакетов (`packages.build`) и проверка поездки
  (`trip.validate`) — работает без LLM и встраивается в обычную воронку. Например, как проверка корзины
  «отель + билеты» перед оплатой.
- **Аналитика**: каждый ход пишет вызовы инструментов и блоки (показаны пакеты, выбран пакет, найдена
  проблема, подтверждена оплата) в логи и в LangSmith. Это готовые события воронки.

Какие бизнес-метрики растут и как их измерить:

| Метрика | За счёт чего | Как мерить |
|---|---|---|
| Конверсия из запроса в бронь | одно сообщение → три готовых варианта, уточнений в среднем 0 | доля сессий с заказом; ходов и секунд до первого варианта (уже в evals) |
| Средний чек, доля поездок «под ключ» | отель, дорога и трансфер в одной корзине и одной сумме | доля заказов с перелётом или трансфером |
| Отмены и обращения в поддержку | проверка состыковок до оплаты, честные «не подтверждено» | доля отмен и обращений по броням через агента против обычной воронки |
| Самообслуживание после покупки | перенос дат и трансфер в том же чате | доля переносов без оператора |

## Локации

Код агента не знает названий городов и районов. Всё о месте лежит в папке `backend/seed/<id>/`:

- `location.json` — пишется руками: районы с описаниями для промпта и точками погоды, аэропорт, вокзалы
  и время до них (если есть поезда), часовой пояс, море и норма температуры воды, сезонность цен,
  тариф такси, подсказки для пустого чата и что выгружать из OpenStreetMap. Формат описан в
  `backend/agent/location.py`;
- `hotels.json` и `meta.json` — выгружает `scripts/fetch_osm.py <id>`: границы районов из OSM,
  расстояние до моря, дорога из аэропорта по OSRM, что рядом.

Как добавить город:

1. Создать `backend/seed/<id>/location.json` по образцу `sochi/location.json`: районы и их OSM-границы
   (relation id), аэропорт, часовой пояс, море (или `null`), поезда (или `null` — тогда только самолёт),
   сезонность и тариф такси.
2. `make seed LOCATION=<id>` — выгрузить отели из OpenStreetMap.
3. `PULSE_LOCATION=<id>` в `.env` и перезапустить.

Промпт, инструменты, погода, поезда, фото и подсказки в интерфейсе берут всё из локации. Один запуск
обслуживает одну локацию. Сценарии evals написаны для Сочи.

## Качество: тесты, сценарии и метрики

**Юнит-тесты** (`make test`, `tests/`) проверяют ядро без модели и сети:

- пакеты: суммы сходятся, уровни упорядочены, бюджет и «без хостелов с детьми» соблюдены, поезда приходят
  в день заезда, гибкие даты находят реальную экономию;
- проверку поездки: каждая несостыковка ловится своим кодом;
- перенос заказа и трансфер после покупки;
- локации: каждая описана полностью, промпт собирается из локации.

**Сценарии на настоящей модели** проверяют результат, а не дословный текст: состояние поездки,
вызванные инструменты, формат и честность ответа. Их 24:

- основные: семья на майские, выходные, сдвиг дат, покупка с кнопкой, только отель, мало данных,
  другой город, инъекция, нехватка бюджета, горы, поезд, выбор района, память между чатами, «запомни»;
- запросы, которых агент не видел при настройке промпта: «тёплое море в ноябре», «Питер на выходные»,
  «Турция всё включено», «с собакой», «дороговато», лимит за ночь, «лыжи в июле», «удиви»;
- после покупки: перенос оплаченного заказа на день позже, трансфер к купленному отелю.

```bash
make evals                                        # в Docker
uv run python -m evals.run                        # локально: все
uv run python -m evals.run buy train --repeat 3   # выбранные, по 3 раза
```

В отчёт (`evals/results/<время>.md` и `.json`) попадают метрики:

- доля сценариев, доведённых до конца;
- сколько уточняющих вопросов до первого варианта;
- ходов и секунд до первого варианта;
- пакеты без ошибок состыковки;
- ходы с ошибкой;
- вызовов инструментов на ход.

Как агент отвечает на незнакомое (из отчёта):

- «Тёплое море в ноябре» — «тёплого моря в ноябре не будет: вода около 16°… это вариант для прогулок,
  а не купания», и всё равно собирает поездку на первую неделю ноября.
- «Питер на выходные» — «собираю поездки только в Большой Сочи… могу собрать похожие выходные в Сочи».
- «Лыжи в июле» — «лыжный сезон не идёт», предлагает горы летом и зимние даты для лыж.

Первый прогон новых сценариев нашёл три проблемы: «с собакой» уходило в пожелание вместо условия
«с животными», на «тёплое море» модель не знала нормы воды, и один ход упал на 503 провайдера.
Это исправлено: удобства передаются прямо в подбор, нормы воды из локации есть в промпте, вызов модели
повторяется дважды.

Основной набор на других моделях: `gemma` — 12/12 ([отчёт](evals/results/20261027-191256.md)),
`gpt-oss` — 9/12 ([отчёт](evals/results/20261027-231612.md)). Эти прогоны были до сценариев с поездом,
выбором района и работы после покупки.

## Наблюдаемость

- **Логи** (`make logs`): по строке на каждый вызов модели (модель, секунды, токены, какие инструменты
  вызывает) и инструмента (ok или ошибка, время, аргументы), а также начало и конец хода с длительностью.
- **LangSmith**: впишите в `.env` `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY` и `LANGSMITH_PROJECT=pulse`,
  затем перезапустите сервис. Каждый ход станет деревом: промпт, ответ модели, вызовы инструментов с входом
  и выходом, токены и время.

## Данные

| Что | Откуда |
|---|---|
| Отели: название, тип, адрес, координаты, звёзды, сайт | OpenStreetMap, 1 358 объектов в шести районах |
| Район, расстояние до моря, первая линия, что рядом | вычислено из геометрии OSM |
| Дорога из аэропорта до отеля | маршрут по дорогам OSM (OSRM) с запасом на пробки |
| Перелёты | реальные недавние цены из кэша Aviasales (Travelpayouts), не бронь |
| Поезда | с `YANDEX_RASP_KEY` — настоящее расписание [Яндекс Расписаний](https://rasp.yandex.ru/): номер поезда, отправление и прибытие на ближайшую к отелю станцию, где он останавливается; цена — из API, если есть, иначе демо; места не проверяются, купить — на rzd.ru. Без ключа или при сбое API (пауза 10 минут) — демо-расписание: время в пути ориентировочное, цена купе условная. Станции и их координаты — настоящие |
| Погода и море | Open-Meteo: прогноз на 15 дней, дальше — те же даты год назад |
| Праздники | производственный календарь isdayoff.ru, с переносами |
| Фото | сайт отеля или Wikimedia Commons, с автором и лицензией |
| Цена и наличие отеля, питание, отмена, такси | демо-модель: класс × тип × район × море × сезон |

Источники подключены адаптерами (`backend/agent/adapters/`), контракт описан в `backend/agent/contracts.py`.
Чтобы подключить настоящий API отелей или билетов, нужно заменить адаптер. Агент, проверки и интерфейс
при этом не меняются.

## Ограничения

- Один воркер и SQLite: запросы внутри сессии идут по очереди через блокировку в процессе. Путь
  к нескольким воркерам — `PostgresSaver` и Postgres вместо SQLite, код агента не меняется.
- Около 25 секунд до первого варианта: агент за один ход ищет перелёты, отели, погоду и гибкие даты.
  Карточки приходят потоком раньше текста.
- Цены отелей, наличие, питание, отмена и такси — демо-модель (честно подписано в интерфейсе и в ответах).
- Один запуск обслуживает одну локацию.

## Структура

- `backend/main.py`, `endpoints.py`, `auth.py` — FastAPI: страница, API, сессии.
- `backend/agent/` — агент на LangChain и LangGraph:
  - `service.py` — граф и поток событий;
  - `tools/` — инструменты;
  - `packages.py` — сборка пакетов;
  - `trip.py` — состояние и проверки;
  - `aftersale.py` — перенос заказа и трансфер после покупки;
  - `location.py` — локация из `backend/seed/<id>/location.json`;
  - `adapters/` — источники данных;
  - `prompts.py` — промпт;
  - `guardrails.py` — фильтр инъекций;
  - `observability.py` — логи.
- `backend/seed/sochi/` — локация: `location.json`, отели из OSM.
- `frontend/` — веб-интерфейс без сборки.
- `tests/` — юнит-тесты ядра.
- `evals/` — сценарии, метрики, отчёты прогонов.
- `docs/` — устройство агента ([docs/AGENT.md](docs/AGENT.md)).
- `scripts/` — выгрузка отелей из OpenStreetMap.

## Запуск без Docker

```bash
uv sync
cp .env.example .env
uv run uvicorn backend.main:app --reload   # http://127.0.0.1:8000
```

Без uv: `python -m venv .venv`, затем `pip install -r requirements.txt` и
`python -m uvicorn backend.main:app --reload`. Версии всех пакетов зафиксированы в `requirements.txt`
и `uv.lock`, прямые зависимости перечислены в `pyproject.toml`.
